**1. Choose the problem.**  
Commit.

**2. Define the problem.**  
What’s wrong, for whom, and why it matters.

**3. Define users.**  
Goals, pressures, risks, context of use.

**4. Identify pain points.**  
Rank the biggest failures in today’s experience.

**5. Note constraints.**  
Legal, technical, environmental, organizational limits.

**6. Decide success metrics.**  
How improvement will be measured.

**7. Form hypotheses.**  
What change should create what outcome, and why.

**8. Define the MVP.**  
Minimum capability to remove the core pain.

**9. Map journeys.**  
Steps users take from start to completion.

**10. Structure information.**  
Navigation, grouping, hierarchy.

**11. Sketch wireframes.**  
Layout and clarity, no visual polish.

**12. Resolve interactions.**  
Errors, edge cases, states, first use.

**13. Design the interface.**  
Visual system applied to a solid structure.

**14. Build a prototype.**  
Make flows realistic and clickable.

**15. Test with people.**  
Observe friction and failure.

**16. Improve.**  
Fix, simplify, repeat.

**17. Document the story.**  
Problem → reasoning → trade-offs → outcome.
